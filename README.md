## 这是什么

买商品房时，楼还在盖，开发商会先装出一间**样板间**——1:1 还原，你走进去，就能想象出未来家的样子。

**WorkLoom 酒店经营样板间，就是酒店经营系统的样板间。** 我们用一份与真实经营毫无区别的数据（30 天 × 全业务域 × 哈希链可验证），把「一家 AI 增强的酒店」完整装修出来：夜班班组、收益曲线、差评处置、断点收敛、技能市场——全部是可点开、可下钻、可验证的真实事件流。

> 客户看到的不是 PPT，不是愿景，而是**自己店买下之后第 30 天的样子**。

## 一、新的业务模式（70%）

### 1.1 酒店经营正在漏钱，而且漏得无声无息

单体酒店同时挂着 6–8 个 OTA 渠道，每个渠道独立后台。这导致「三失」——**失控**（价格倒挂、超售漏售）、**失时**（调价、回评总是慢半拍）、**失准**（信息不同步，决策靠感觉）。行业测算：这类混乱每年吞掉单体酒店 3–8% 的营收。一家年营收 100 万的 30 间房酒店，就是每年 3–8 万——**相当于白养一个前台**。

更深一层的问题是：店长每天 5.5 小时耗在机械重复上（改价、对账、回评、做表），真正值钱的判断（收益策略、客诉、服务质量）反而没时间做。而夜班前台是整个人力结构里最脆弱的一环——**招聘难、留人难、出错难究**。

### 1.2 不是「AI 帮你干活」，是「活儿的干法变了」

这套系统最有价值的不是自动化，而是**工作范式的重构**——回到每件事的目的，用全新方式达成，让原来的工作本身消失：

| 原来的事 | 真正目的 | 范式重构之后 |
|---|---|---|
| 每晚 1–2 小时**夜审** | 账实相符 | 每笔业务发生时即五元入账、哈希链锁定——「账」在发生瞬间已核。**夜审这个动作消失**，清晨只看差异项 |
| 手写**交接班**本 | 信息连续 | 事件库天然连续、不可篡改。下一班不读人写的交接，直接查系统投影+签收留痕。**交接从转述变成查询** |
| 店长每天**手动调价** | 价格贴合市场 | 价格成为围栏内的连续函数（涨幅 ≤8% auto / 保底价熔断 / 夜班微调 ≤3%）。店长从调价操作员上移为**策略制定者**——策略即配置 |
| **差评**事后补救 | 减少口碑伤害 | 防御窗口前移到在住期间（离店前补救）；差评沉淀为组织免疫的训练样本，**同类问题越来越少是工程结果** |
| 月底**做报表** | 回答经营问题 | 数据已在中台，报表从「被制作的产物」变成**自然语言提问的即时答案** |
| 前台**接电话** | 即时准确应答 | AI 语音前台 24h 应答（知识库自动生长），前台只剩一条「例外通道」。对民宿业主，这意味着**晚上可以关机** |
| 无人酒店**断点**兜底 | 服务不中断 | 断点强制根因四分类（未分类不许结案），同类 ≥3 次自动固化。**断点率单调收敛=模式可复制** |

### 1.3 三个客群，三套价值

**一个底座，同一套能力，卖给三种人三种完全不同的东西：**

#### 🏨 低星单体酒店（20–50 间）——卖 ROI
> **一年省 17 万，一个月回本。**

中性测算：降本 9.8 万（每天省 5.5 小时机械劳动）+ 增收 7.2 万（堵六大流失点）。最保守情景 11.5 万也是订阅费 3 倍以上。夜班替代一项（年化 2.8–4.2 万）即覆盖全年订阅，其余全是净赚。

#### 🏡 民宿（5–20 间）——卖自由
> **把夜晚还给业主。**

民宿业主最大的痛不是经营指标，是「7×24 人质状态」。AI 语音前台接管深夜来电（78% 独立应答，转人工默认转值班手机而非叫醒业主）；内容营销旗舰位（小红书/种草是民宿命脉，每次发布必审、私域触达防打扰）。

#### 🤖 无人酒店——卖断点收敛与管理半径
> **断点不是事故，是资产。你的第 5 家店比第 1 家店更好管。**

三级兜底（AI→远程→现场）+ 断点根因闭环，断点率逐周单调下降；业主驾驶舱一屏管多店，管理半径从 3–5 家扩到 5–8 家。年化价值 14–21 万/店，占营收 10–15%，且随店数线性放大、无需线性加人。

### 1.4 一条贯穿所有客群的续费逻辑

**经验资产化。** 酒店业流失率 30–50%，优秀店长的调价手感、客诉话术过去都随人走。在这套系统里，经验显性化为技能（25 个官方套件 + 团队自建 + 行业共享），新员工入职第一天就站在前任全部经验的肩膀上。**订阅即保险，续费即复利。**

## 二、背后的技术与设计理念（30%）

### 2.1 业界前沿的工程底座

- **事件溯源 + 哈希链**：全业务以五元事件（谁/何时/对什么/做了什么/规则影响）入账，逐条 SHA 链式锁定，`pnpm db:verify-chain` 逐条重算验证。**包括系统自己的操作也不可篡改**——这是给客户的信任底座，也是售前的现场演示环节。
- **围栏引擎（fence-engine）**：所有 Agent 动作 100% 经过三级判定瀑布——`auto` 放行 / `review` 挂起审批 / `block` 熔断告警。deny 优先并集、求值异常按 block（拒绝默认）、基线单调守卫（任何上层配置**只可收紧不可放宽**）。酒店基线 R1–R20 覆盖调价/退款/差评/触达/采购/排班/安全/倒挂/超售/SLA/损耗。
- **夜班班组状态机**：候选清单→人类确认→围栏内全自治→一键暂停 ≤60s 全端生效→断点续跑→08:30 三段投影决策包（✓已完成/◆待审批/▲需介入）。
- **双角色 RLS 隔离**：事件写入唯一入口走 gateway 角色 + SECURITY DEFINER 函数（search_path 锁死、双 GUC 校验、断链拒写），行级安全策略兜底多租户隔离。
- **技能市场与意识系统**：高频相似任务自动检测，周频产出固化建议，店长一键把「重复劳动」固化为触发器/SOP/技能——**系统越用越聪明**。
- **售前数字孪生**：确定性随机种子生成 30 天全业务域数据（任意重跑逐字节一致），快照随仓库分发，30 秒恢复；样板间管家（twin-genie）实时兜底补数，**演示永不冷场**。

### 2.2 人性化的产品设计理念

- **拒绝默认（fail-closed）**：宁可错杀，不可错放。数据缺失时系统熔断而非猜测——信任来自「它不会背着我做决定」。
- **三手势决断**：审批=看清快照、一句话理由、一个手势。人类的权威被保留在最需要判断的地方，机械的部分一律消失。
- **只紧不松**：围栏基线任何 patch 只能加严。客户的每一次自定义都在让系统更安全，而不是更危险。
- **把夜晚还给业主**：技术的终极指标不是替代了多少工时，而是**人能不能睡个整觉**。
- **断点是资产**：每一次系统做不到的事，都必须让系统下一次做得更好——失败被制度化为学习样本。

## 三、亲自体验这间「样板间」

```bash
pnpm install && pnpm db:migrate
pnpm db:seed && pnpm demo:twin      # 种子 + 30 天经营模拟（约 1300 条事件）
pnpm dev                            # 打开工作台：P1 晨间简报 → P11 价格健康页

# 售前现场（免模拟，30 秒进入经营态）
pnpm demo:twin:restore              # 从随仓快照恢复
pnpm demo:twin:live                 # 样板间管家：实时补数 + 场景按需合成 + 空态守卫

# 信任收口（可当着客户的面跑）
pnpm db:verify-chain                # 全库哈希链逐条重算
```
