## 1. 产品定位

**WorkLoom 织元是一个企业级 AI 业务编排与执行底座（企业智能执行中枢，Enterprise AI Execution Layer）：接入并调度企业现有的各类系统、工具与数据，将行业流程自动化为可监控、可执行的事件流，最终由「数字员工」（AI Agent + 人机协作）完成业务目标交付。**

对外统一口径三句话：

1. 我们不替代你的系统，我们让你的系统被 AI 驱动起来。
2. 我们不生产建议，我们交付已执行的业务动作。
3. 人只做三件事：定目标、划边界、担责任；其余交给数字员工。

## 2. 产品边界

### 2.1 我们做的（核心能力）

| 维度 | 具体内容 | 对应层 |
|---|---|---|
| 系统连接 | 接入企业现有系统（飞书、钉钉、社媒后台、营销平台、剪辑工具等），不做系统本身 | 连接层 |
| 能力调度 | 通过 API / CLI / AI 操作电脑三种方式调用各系统能力 | 连接层 |
| 流程编排 | 将行业流程抽象为自动化任务流：执行 → 监控 → 拿结果 | 编排层 |
| 数据打通 | 打通组织内多源业务数据，作为调度与决策的基础 | 数据层 |
| 角色交付 | 支持配置不同「数字员工」角色，完成端到端业务交付 | 角色层 |
| 事件驱动 | 底层以「可监控、可执行的事件」为核心单元（区别于传统 IM 的消息流） | 事件层 |

### 2.2 我们不做的（明确排除）

| 维度 | 具体内容 |
|---|---|
| 业务系统本身 | 不建垂直业务系统（如酒店 PMS、抖音后台、垂直 SaaS 等） |
| 行业 Know-how Skill | 不做带强行业属性的垂直技能/Agent（如酒店收益管理算法、医疗诊断逻辑）；只提供底座，行业内容由行业伙伴或客户自己沉淀 |
| 传统 IM 功能 | 不是聊天工具，不是 Slack/飞书替代品；产品定位与对外物料不使用「IM」作为品类定义 |

**边界判定规则**：两个以上行业都需要 → 进底座；只一个行业需要 → 留行业侧；含行业业务词汇（房价/询盘/保底价）→ 不进底座；底座只定机制，不内置行业阈值（行业阈值由行业方配置，客户只可收紧不可放宽）。

## 3. 核心架构

### 3.1 三层模型 + 事件驱动底座

[[SVG-ARCH]]

```
┌───────────────────────────────────────────────────┐
│  第3层：交付层（数字员工 / 角色配置）                  │  ← 配置不同员工角色，完成业务交付
│      Agent preset · 技能绑定 · 围栏授权 · 工时留痕     │
├───────────────────────────────────────────────────┤
│  第2层：编排层（流程自动化引擎）                       │  ← 行业流程 → 自动化任务流 → 执行/监控/结果
│      任务派遣 · 规则围栏 · 审批流 · 定时/事件触发       │
├───────────────────────────────────────────────────┤
│  第1层：连接层（系统接入与数据打通）                   │  ← API / CLI / AI操作电脑接入现有系统，打通数据
│      平台适配器 · 凭据管理 · 健康探针 · 数据映射        │
└───────────────────────────────────────────────────┘
                    ↓ 贯穿三层的底座 ↓
        底层核心：事件驱动（Event-Driven）
        一切动作 = 可监控、可执行、可追责的事件（五元事件）
```

### 3.2 关键设计原则（运行时不变量）

| # | 原则 | 工程含义 |
|---|---|---|
| 1 | 事件 append-only | 事件库禁 UPDATE/DELETE（数据库角色权限强制）+ 哈希链防篡改；一切视图（结果/审计/账单）是事件日志的只读投影，不建额外报表管道 |
| 2 | 写类动作 100% 过围栏 | auto → 放行 / review → 挂起转审批 / block → 熔断+告警；自动化触发与子调用走同一条判定流水线，无后门 |
| 3 | 无回执 = 未核实 | 外部系统未确认生效的动作标「未核实」，不得宣称完成，进「需介入」 |
| 4 | 模型可见即已记录 | 任何进入模型上下文的信息必须先落事件日志；留痕覆盖率 100%，不达标的构建不得发布，无降级 |
| 5 | 禁止无痕操作 | 回滚、围栏变更、任务终止等一切人工动作本身都是事件；回滚 = 逆向补偿事件序列，原事件永不修改 |

### 3.3 五元事件协议（核心 Schema）

```json
{
  "event_id": "E-8821",
  "who":      { "type": "human|agent|system", "id": "...", "version": "..." },
  "context":  { "tenant_id": "...", "workspace_id": "...", "time": "...", "channel": "...", "stage": "..." },
  "object":   { "type": "...", "id": "..." },
  "decision": { "action": "...", "before": {}, "after": {}, "basis": ["..."], "memory_refs": ["..."] },
  "rule_impact": [ { "rule_id": "...", "version": "...", "result": "pass|review|blocked|conflict" } ],
  "receipt":  { "synced": true, "snapshot_uri": "...", "verified_at": "..." },
  "model_trace": { "model_id": "...", "tier": "standard|flagship", "window": "peak|off-peak", "credits": 0 },
  "hash": "sha256(prev_hash || payload)"
}
```

字段说明：`event_id` 服务端单调递增 + (租户, 编号) 幂等键，重复写入丢弃；`object.type` 枚举行业化扩展；`receipt` 为执行回执位（无回执 = 未核实）；`hash` 为前序事件哈希链，防篡改。

## 4. 接入方式（三种，全量支持）

| # | 方式 | 适用对象 | 要求 | 验收标准 |
|---|---|---|---|---|
| 1 | API 接入 | 有开放接口的系统（飞书/钉钉/主流 SaaS/营销平台） | 标准接口对接，首选路径，零 token 成本；统一抽象为平台适配器 | 读写动作均返回结构化回执；凭据走凭据存储，不出现在提示词与事件明文 |
| 2 | CLI 接入 | 开发/运维类工具 | 命令白名单 + 沙箱执行；输出结构化解析为事件 | 非白名单命令被拒绝并留痕；执行结果 100% 落事件 |
| 3 | AI 操作电脑 | 无开放接口的老系统/封闭式 SaaS | 模拟人工操作（浏览器/桌面 GUI）；执行前页面特征探针健康检查，探针失败自动降级或转人工，禁止盲目点击；验证码一律暂停转人工；桌面操控用虚拟输入通道，人接管即让出控制并留痕；高危操作逐次授权 | 探针失效标「渠道适配失效」并转人工；频次自律（单平台请求间隔 ≥3s，遵守 robots） |

**降级链**：API 优先 → CLI → AI 操作电脑（确定性剧本 → 自主探索仅冷启动，探明后固化为剧本）→ 人工接管（进「需介入」）。能走 API 就不模拟点击，能跑确定性剧本就不烧 token。

### 5.5 数据层（FD）

| 编号 | 功能 | 优先级 | MVP | 字段级描述与验收标准 |
|---|---|---|---|---|
| FD1 | 多源数据打通 | P0 | 是 | 打通 MVP 接入的 2–3 个系统的基础数据字段，支持流程内数据传递；字段映射表 + 数据流向留痕。验收：MVP 流程内跨系统数据传递无人工搬运 |
| FD2 | 业务档案（一 X 一档） | P0 | 是 | 每工作区一份结构化档案，数字员工生成/执行前必读「档案 + 阶段 + 目标」三要素，缺一拒绝执行；档案中禁用承诺（forbidden）为硬约束，优先级高于一切规则与推理 |
| FD3 | 脱敏网关 | P0 | 是 | 事件写入 / 模型出站 / 共享回流三处必经；脱敏失败即拦截并记安全事件，禁止降级为原文。验收：注入含 PII 的上下文，出站报文 0 命中原文 |
| FD4 | 组织记忆 | P1 | — | 三级作用域（工作区/角色/单次运行）；每条记忆记录来源事件 ID（归因）与置信度（默认 0.5）；审批手势（批准/修改/驳回，权重 1/2/3）写回后自动校准 |

### 5.6 横向能力（FX）

|---|---|---|---|---|
| FX1 | 多租户工作区隔离 | P0 | 是（最小） | 行级隔离（RLS 强制）；越权查询返回空而非 403（防侧信道）。MVP 单租户多工作区即可。验收：跨租户读取测试全部返回空 |

## 6. 关键硬约束（L）与异常处理（E）

### 6.1 硬约束（可测试）

| 编号 | 约束 |
|---|---|
| L1 | 事件库 append-only：禁 UPDATE/DELETE，由数据库角色权限强制；一切人工动作本身都是事件，禁止无痕操作 |
| L2 | 所有事件写入必经安全网关（权限校验 → PII 脱敏 → 高风险授权），任何模块禁止绕过直写 |
| L3 | 围栏判定对所有写类工具调用生效，含自动化触发器与子调用，不允许「自动化绕过审批」的暗道 |
| L4 | 基线围栏规则只可收紧不可放宽；放宽基线的配置加载即拒绝并留痕 |
| L5 | 数字员工角色未声明 fence_bindings 时，系统级禁止其执行写类动作（加载时强制校验） |
| L6 | 关键数字必须来自工具回执；无回执标「未核实」，不得自动执行 |
| L7 | 凭据永不出现在提示词与事件明文，事件只记引用 ID |
| L8 | 模型出站内容必经脱敏网关，插件不可绕过；脱敏失败即拦截，禁止降级为原文 |
| L9 | 单工作区并发任务 ≤10，超出排队且对用户可见；同一对象并发写互斥（对象级写锁） |
| L10 | AI 操作电脑遵守频次自律（单平台请求间隔 ≥3s、遵守 robots）；验证码/二次认证一律暂停转人工，禁止绕过 |
| L11 | 禁止静默换模型：任何切换/降级必写事件 |
| L12 | 「模型可见即已记录」运行时断言：任何进入模型上下文的信息必须先落事件日志 |

### 6.2 异常处理

| 编号 | 异常 | 处理策略 |
|---|---|---|
| E1 | 事件库磁盘写满 | 转只读保护 + 执行全转必审 + P0 告警；恢复后补偿写入，禁止静默失败 |
| E2 | 脱敏失败（识别器未命中新型 PII） | 拦截该批次 + 记安全事件 + 告警；禁止降级为原文上行 |
| E3 | 平台改版致剧本探针失效 | 标「渠道适配失效」+ 转人工/降级一层；禁止盲目点击；失效事件留痕 |
| E4 | 进程崩溃（kill -9） | 事件流重放断点续跑且幂等 |
| E5 | 验证码/二次认证出现 | 一律暂停转人工，禁止绕过 |
| E6 | 工具回执缺失（外部系统未确认生效） | 动作标「未核实」，不得宣称完成；进「需介入」 |
| E7 | 并发写同一业务对象 | 对象级写锁互斥；超时转「需介入」，禁止强制抢锁 |
| E8 | 围栏规则求值异常 | 该规则按 block 处理（宁可错杀）+ 配置错误告警；禁止异常时默认放行 |
| E9 | 伪造审批回调 | 签名校验失败即拒绝 + 安全事件；openid 不在成员映射即拒绝 |
| E10 | 审批时目标对象已被后续动作修改 | 提示冲突并刷新最新 before/after，禁止基于过期快照审批 |
| E11 | 主模型不可用 | 按降级链切换 + 留痕；全链不可用则排队或转「需介入」 |
| E12 | 单任务消耗异常飙升 | 熔断挂起 + 告警 + 留痕 |
| E13 | 越权调用（跨租户/越版本/无权限角色） | 跨租户返回空；越版本/越权限服务端 403 + 留痕；前端隐藏入口而非置灰 |
| E14 | 一键暂停 60s 未完全生效 | 升级 P0 告警 + 强制隔离会话；超时不静默 |

## 7. MVP 定义

### 7.1 MVP 目标

验证「**底座 + 连接 + 单场景自动化**」的可行性：一条行业流程，从事件触发到数字员工端到端交付结果，全程可监控、可审批、可留痕。不做大而全。

### 7.2 MVP 范围

| 层 | MVP 内容 | 准出验收 |
|---|---|---|
| 连接层 | 接入 2–3 个高频系统（如飞书/钉钉 + 1 个业务后台），至少覆盖 API 和 AI 操作电脑两种接入方式 | 每种方式各有 1 个系统跑通读写动作；写动作 100% 过围栏 |
| 事件层 | 标准事件格式（FE1）+ 事件注册/监听/执行/回调（FE2）+ append-only 事件库（FE3） | 四接口闭环；抽样事件五元完整率 100%；旁路直写与 UPDATE 被数据库拒绝 |
| 编排层 | 1 个简单行业流程自动化（FO2）+ 围栏（FO3）+ 审批（FO4）+ 任务线程（FO1） | 流程端到端跑通；review 级动作必挂起进审批队列；审批后执行结果回链事件 |
| 角色层 | 配置 1 个基础数字员工角色（FR1），完成上述流程端到端执行 | 未声明围栏时写动作被系统拒绝；角色执行全程留痕可归因 |
| 数据层 | 打通 2–3 个系统基础数据字段（FD1）+ 业务档案（FD2）+ 脱敏网关（FD3） | 流程内跨系统数据传递无人工搬运；出站内容 0 PII 原文 |

### 7.3 MVP 明确不做

- 多行业通用模板
- 复杂的员工权限体系（MVP 仅管理员/操作员两角色）
- 可视化流程编排器（初期用配置化/代码化替代）
- 行业 Know-how 技能市场
- 夜班班组、巡检、模型峰谷路由、组织记忆、计费、私有化（均为 P1，MVP 之后）

### 8.3 MVP 运行链路（一次任务全生命周期）

```
任务发起（配置化/派遣入口）
→ 安全网关（权限校验 + PII 脱敏 + 高风险授权）          [flydata-core + Presidio]
→ 角色装配（工具集 + 提示词段 + 围栏声明 + 档案上下文）    [preset loader，缺三要素拒绝执行]
→ Agent Loop（dsh）逐步执行，每步工具调用过瀑布：
     围栏三级判定（auto/review/block）→ 单调守卫 → 沙箱包裹 → 超时/计量
→ 工具执行（API 适配器 / Stagehand 剧本，执行前健康探针）
→ 五元事件写入事件库（必经安全网关，含执行回执位）
→ review 级动作 → 挂起 → 审批队列（端内 / IM 卡片）→ 手势回写事件
→ 交付：结构化结果 = 事件日志的只读投影（before/after + 证据快照 + 决策链路）
```
